# 动漫形象数字人 (anime presenter) — shared contract

The 「卡通讲解员」 of 口播剪辑 / 录屏讲解 grows into a reusable **「我的动漫形象」** that talks with the user's own
voice, in three tiers the user picks per video:

| Tier | Engine id | What moves | Cost | Needs |
|---|---|---|---|---|
| 1 · free (default) | `sprite` | mouth shapes per syllable, blinks, bob / sway / breathing | free, local | nothing |
| 2 · local model | `tha3` | mouth vowels, eyes, eyebrows, head turn, body sway, breathing (Talking Head Anime 3) | free, local | optional install; NVIDIA (CUDA) fast, CPU slow |
| 3 · cloud | `runway`, `volc`, `vidu` | whole face (+ upper body for some modes), generated by the provider | per second, BYOK | the user's own key |

## Character record (anime-character.js owns it)

Characters live outside projects so they are reused across videos:
`<DSH_VIDEO_HOME>/anime-characters/<id>/character.json` (+ the files it names, all in the same folder).

```jsonc
{
  "id": "c-20261124-ab12cd",          // folder name, [a-z0-9-]
  "name": "我的动漫形象",
  "version": 3,                        // bumped on every change of the picture / face marks / sprites
  "createdAt": "…", "updatedAt": "…",
  "source": { "kind": "photo" | "cartoon", "file": "source.png" },
  "stylize": { "method": "cloud" | "local" | "none", "provider": "seedream…" },
  "portrait": "portrait.png",          // RGBA, background removed, cropped to the character, upright, ≤ 1024 px
  "width": 768, "height": 1024, "aspect": 0.75,
  "face": {                            // normalised to the portrait (0..1); from the user's clicks, editable
    "mouth": { "x": 0.5, "y": 0.31, "w": 0.09 },
    "eyes": [{ "x": 0.44, "y": 0.24, "w": 0.07 }, { "x": 0.56, "y": 0.24, "w": 0.07 }]
  },
  "sprites": { "source": "procedural" | "tha3" | "cloud" | "user", "mouths": { "half": "m-half.png", "a": "m-a.png", "o": "m-o.png", "i": "m-i.png" }, "blink": "eyes-closed.png", "boxes": { … } },
  "tha": { "image": "tha-512.png", "ok": true },   // tier 2 input (512×512 RGBA, see anime-local.js)
  "cloud": {                                        // tier 3: provider-side ids, created once per portrait and reused
    "runway": { "avatarId": "…", "portraitSha": "…", "keyColor": "green", "status": "READY", "createdAt": "…" },
    "volc":   { "avatarId": "<a resource_id>",          // 火山引擎 形象 (one per drive mode)
                "roles": { "loopy": { "resourceId": "…", "portraitSha": "…", "keyColor": "green", "createdAt": "…" },
                           "normal": { "pending": true, "taskId": "…", "tosKey": "…", "portraitSha": "…" } } }
    // Vidu needs no provider avatar (picture + voice go with every task)
  }
}
```

`getCharacter(id)` returns the record plus `dir` (absolute folder). Engines only **read** the record, except tier-3
engines, which store their provider ids through `saveCharacterCloudId(id, provider, data)` (anime-character.js).

## Voice → motion (anime-visemes.js owns it)

`computeVisemeTrack({ audioAbs, fps = 30, captions = [] })` →
```jsonc
{ "fps": 30, "frames": 1234, "durationSec": 41.13,
  "open":  [0..1 per frame],               // mouth opening
  "shape": ["closed"|"half"|"a"|"o"|"i"],  // mouth shape per frame (sprite / tha3 vowel)
  "vowels": { "a": [..], "i": [..], "u": [..], "e": [..], "o": [..] },   // 0..1 weights per frame (tier 2)
  "blink": [0..1 per frame],               // eyelid closure
  "talk":  [0..1 per frame],               // speaking activity (head motion intensity)
  "words": [onset seconds] }
```
Language independent (loudness + spectral shape, no dictionary); captions only add word onsets.

## Engine interface (tiers 2 and 3)

```js
/** @returns {Promise<{ ok: true, path, durationSec, fps, width, height, engine, note, cost? }>} */
renderPresenterClip({
  character,      // record from getCharacter(id) (with `dir`)
  audioAbs,       // the cut's final voice track (WAV); the clip must match its timeline exactly, from 0
  outAbs,         // .webm, VP9 + alpha (yuva420p): transparent background, cropped to the character
  fps = 30,
  maxHeight = 720,
  track,          // computeVisemeTrack() result (tier 2 drives the pose with it; tier 3 cuts the voice at its pauses)
  signal, onProgress({ message, pct }), onChild(child),
  // tier 3 only (anime-engines.js passes them):
  engine,         // 'vidu' | 'volc' | 'runway'
  mode,           // volc: 'loopy' | 'normal' | 'loopyb'; vidu: '540p' | '720p'; '' = the saved default
  confirmedRmb,   // the amount the user agreed to for this run (never stored)
  saveCloudId(provider, data),   // remember a provider-side avatar on the character
})
```
- Throw `Error` with a plain-Chinese message; set `err.code`: `NOT_INSTALLED` | `NO_KEY` | `BILLING` | `UNSUPPORTED_IMAGE` |
  `PROVIDER_ERROR` | `TIMEOUT` | `COST_NOT_CONFIRMED`.
- Clips are cached by `sha1(engine + character.id + character.version + audio sha256 + options)` next to `outAbs`;
  a cached clip is never generated (or paid for) twice.
- Tier 3 never runs without the caller's explicit cost confirmation: `estimatePresenterCost({ engine, durationSec, mode,
  character? })` → `{ rmb, usd?, unit, basis, pieces, priceDate, sourceUrl }` is shown first; `planAnimePresenter`
  requires `confirmedRmb >= estimate.rmb`, and anime-cloud.js checks again against what is really still to pay.

## Rendering

- `sprite`: no clip — the talk kit (remotion-lib/talk-kit.tsx) and the HTML draft draw portrait + mouth / blink patches
  per frame from the viseme track, plus the existing bob / sway (talk-mascot.js mascotPose).
- `tha3` / cloud: the alpha WebM plays once from 0 in the presenter box (no loop, no extra bob).

## One cut (anime-engines.js `planAnimePresenter`, called by talk-mascot.js `planMascot` for a `characterId`)

The cut's `talkPack.mascot` (script.json):
```jsonc
// free tier
{ "type": "anime", "engine": "sprite", "characterId": "c-…", "characterVersion": 3, "path": "assets/.mascot/anime-c-…-v3/portrait.png",
  "sprites": { "mouths": { "half": "…/m-half.png", "a": "…", "o": "…", "i": "…", "closed"?: "…" }, "blink": "…/eyes-closed.png",
               "boxes": { "mouth": { "x", "y", "w", "h" }, "blink": { … } } },          // shares (0..1) of the portrait
  "visemes": { "fps": 30, "shapes": "cchhaaoo…", "blinks": [58, 173], "words": [0.42, …] },
  "keyed": true, "aspect": 0.75, "corner": "bl", "size": "m", "envHz": 12.5, "env": [0..100], "words": [ … ], "note": "…" }
// local model / cloud
{ "type": "anime-clip", "engine": "tha3" | "runway" | "volc" | "vidu", "path": "assets/.mascot/anime-c-…-<engine>-<key>.webm",
  "durationSec": 41.1, "cost": { "rmb": 12.3 } | null, "keyed": true, "aspect": …, "corner", "size", "note" }
```
- The setting (`talk-pack.js cleanMascotSetting`): `{ characterId, engine, mode?, corner, size, confirmedRmb? }`;
  `confirmedRmb` passes through one build only — `storedMascotSetting` never saves it with the project.
- A tier-2 / tier-3 problem (not installed, no key, cost not confirmed, provider error) never fails the cut: the free tier
  is used and `fallback: { engine, code, reason }` + a plain-Chinese `note` say why.
- `remotion-generator.js syncRemotionPublicAssets` copies the sprite pictures into the Remotion `public/` folder.

## Tier 3 · cloud (anime-cloud.js)

Official APIs only, with the user's own account (prices checked 2026-11-24 on the official pages):

| Engine | API | Price | Notes |
|---|---|---|---|
| `vidu` | Vidu S2-Avatar 离线版: `POST https://api.vidu.cn/ent/s_avatar/offline` (`api.vidu.com` abroad), poll `GET /ent/v2/tasks/{id}/creations`, `Authorization: Token …` | 1 credit/s, 1 credit = 0.03125 元 (≈ 1.9 元/min); failed tasks refunded | picture + voice inline (data URIs); "any style" per the docs; 540p / 720p same price |
| `volc` | 火山引擎 单图音频驱动: `CVSubmitTask` / `CVGetResult` at `visual.volcengineapi.com` (Version 2022-08-31, region cn-north-1, service cv, HMAC-SHA256 signature as the official SDK) | 0.3 元/s + 0.1 元 per 形象 (≈ 18 元/min); failures free | 形象 once per picture and mode (`…create_role_loopy` → `resource_id`), then `realman_avatar_picture_loopy` + `audio_url`; modes 灵动 (default, 512×512, anime-friendly) / 普通 / 大画幅灵动 (≤ 45 s per task) |
| `runway` | Runway Characters: `POST /v1/avatars` (once), `POST /v1/avatar_videos` (`gwm1_avatars`, speech type audio), poll `GET /v1/tasks/{id}`, `X-Runway-Version: 2024-11-06` | 1 credit / 3 s, 1 credit = 0.01 美元 (≈ 1.5 元/min) | needs an international card; big files go through `POST /v1/uploads` |

- **Picture:** the transparent portrait, bottom-centred on a flat key colour (green; blue when the character wears a lot
  of green), exactly 3:4 (4:3 for a wide character) — `cloud-input-<sha>-<colour>-<W>x<H>.png` in the character folder.
- **Pieces:** the voice is split at pauses into the fewest pieces the service accepts (Vidu 60 s, Runway 120 s,
  火山引擎 170 s / 大画幅 42 s), on frame boundaries; FFmpeg keys the colour out (chromakey + despill), joins the pieces
  frame-exactly, crops to the character and writes VP9 + alpha. A background the service did not keep plain is refused
  (`PROVIDER_ERROR`) instead of showing a coloured box.
- **Never paid twice:** `<outAbs folder>/.anime-cache/cloud-<engine>-<key>/job.json` records every task id the moment it
  is submitted and every downloaded piece; a stopped / crashed / re-keyed run polls the same tasks or re-uses the files
  (no confirmation needed when nothing is left to pay). Provider avatars are keyed by the portrait's SHA-256, so editing
  face marks does not create (pay for) a new 火山引擎 形象.
- **火山引擎 needs public links:** picture and voice go to the user's own TOS bucket through the S3-compatible endpoint
  (`<bucket>.tos-s3-<region>.volces.com`, pre-signed SigV4 URLs) and are deleted after use.
- **Keys:** `.dsh-video-anime-cloud.json` in the writable workspace (gitignored, never in a project or the bundle);
  `DSH_VIDEO_ANIME_CLOUD_CONFIG` redirects it (tests). The studio panel 「云端动漫数字人 · 密钥」 (`animeCloud`) edits it;
  routes `GET|POST anime/cloud` (masked) and `POST anime/cloud/test` (free key check: read-only calls, a made-up task
  query, a tiny TOS write + delete — never a generation).
- **Not yet verified with real accounts:** everything above follows the official documents and is tested against a
  simulated network (scripts/tests/anime-cloud.test.mjs); how well each service animates a given anime picture and keeps
  its plain background has to be tried with a real key.
